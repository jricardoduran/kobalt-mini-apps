# Qipu MCVT 0.3.0-rc.3 · ATM-C — API de Transformación Mutable basada en Coordenadas
Complemento compatible con QIPU-META-1. La trayectoria es fuente; sus preguntas derivan geometría y contenido. La sintaxis general precede a la trayectoria; la geometría por primera aparición no se preasigna. MCVT actual conserva DEF por ser un perfil declarativo; T13 histórico admite otras constituciones. No mezclarlos.
## Fronteras
Entrada JSON nominal o lista: contexto + tratamiento + selector + manifestación. Traductor de entrada resuelve en el corte correcto, normaliza coordenadas [t,v,i], conserva nombres solo donde no existe posición. Traductor a acontecimiento usa el formato histórico nominal T120/T101; no cambia bytes ni formato del núcleo. El motor valida admisibilidad y plan; CAS/PAO confirman. Un rechazo no constituye. Traductor de salida proyecta una respuesta derivada a lista o JSON. No hay escritura al consultar ni esquema duplicado.
- En contexto C: ["C",["SET",[0,2,1],10]], ["C",["ADD",[0,2,1],2]], ["C",["SUB",[0,2,1],1]]. SET reemplaza la manifestación actual, no todo el producto ni el historial.
- JSON externo: {"context":"C","op":"SET","coordinates":[0,2,1],"value":10}; nominal: {"context":"C","op":"SET","table":"Producto","parameter":"Stock","identity":"SKU-A","value":10}. Se rechazan campos adicionales o mezclas. El primer SET de un parámetro declarado puede materializar vector; ID puede constituir identidad independiente. No se asignan posiciones futuras. Una lista mixta permite representar primeras apariciones; las coordenadas numéricas deben existir. DEF y ACT preservan el perfil existente. ACT multi-fila atómico solo para acción declarada, no batch genérico; múltiples SET son múltiples hechos.
- Lecturas vinculadas al contexto: [] devuelve geometría en orden real de constitución (cada tabla [nombre,identidades,[[vector,dominio]...]]); [t] geometría de tabla; [t,v] pares [i,x]; [t,v,i] escalar o null si celda ausente. Coordenada inexistente es error. project(t,i) devuelve [t,i,identidad,[[v,x]...]], json(t,i) deriva objeto de conveniencia. contract() es lista de declaraciones del perfil, con referencias de declaración, no posiciones de materialización. Una pregunta no necesita cambiar la trayectoria. El atlas amplía leyes de recorrido sin convertir sus preguntas didácticas en opcodes.
- Contexto no es autenticación: el adaptador debe vincular una identidad estable de trayectoria/vista y política, no permitir que el cliente elija libremente autoridad. Posiciones conservadas por extensión, no portable entre geometrías. La respuesta incluye contexto y corte; el corte no es condición de escritura automática: SET se admite sobre actualidad, ADD/SUB se reevalúan. Para evitar lost update semántico hace falta precondición contractual explícita; CAS de almacenamiento no equivale a compare-and-set del usuario.
- Adaptador local: resolución en lectura coherente dispersa; delega a outbox existente con solicitud nominal resuelta estable, persistencia exacta antes de envío, retry por origen. PHP prepara bytes y permite reenvío; el cliente conserva bytes antes de enviar. No autenticación. En cooperación requestCoordinate resuelve contra réplica C dentro de la cola local y conserva T101; factCoordinate usa private:<id> y L. Nunca escribir directamente C; la autoridad mantiene Q/R/C. Las funciones antiguas permanecen por compatibilidad, con orden antiguo [t,i,v]; no mezclar.
- La traducción nominal/posicional es equivalente para selectores resueltos en la misma geometría; no necesariamente inversa en toda solicitud. JSON pierde coordenadas si no se conserva contexto. No confiar en precio de Venta-v1 ni implementar permisos en traductor.
- No cambia Kernel.js/PHP, PAO, K5B, T120/T101, M3E1. No reinterpreta bytes históricos. La nueva lectura sparse puede caer al Map completo; no se promete reducción universal.
