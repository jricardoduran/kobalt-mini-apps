# Qipu MCVT 0.3.0-rc.4-a.1 — A: fenómenos históricos y reconocimiento conjunto
Candidato experimental, extensión conservativa de RC.4 en las pruebas efectuadas. Prioridad: A; se conserva B y la composición A/B. No sustituye RC.3 ni los formatos T120/T101.
## 1. Método de diseño
Preguntar si un componente necesita una manifestación terminal, una geometría interior o un fenómeno histórico con su propio ámbito de preguntas. Todas las manifestaciones tienen historia en la trayectoria exterior; constituir una trayectoria hija permite disponer de una secuencia de acontecimientos propia, cortes locales, exportación exacta y preguntas históricas delimitadas. No crear un motor histórico por aplicación. La UI proyecta respuestas y emite intenciones; la autoridad interpreta y reconoce. Definir parámetros no basta cuando existen restricciones de negocio: se requieren tratamientos y condiciones de admisibilidad.
Ejemplos: precio = manifestación; fotos = vector; variantes = tabla; ciclo de vida de una venta = trayectoria; entrega = trayectoria dentro de venta; proyecto = trayectoria que contiene tabla de colaboradores y trayectoria de tarea. Estas son elecciones semánticas, no una obligación de modelado.
## 2. Ley constitutiva
Sea el prefijo exterior Gamma_n. Si MOUNT introduce P en una celda y las extensiones reconocidas APPEND aportan S_j, la trayectoria hija en n es P || S_1 || ... || S_k. Su geometría es Fold_G de esa secuencia; no se altera el binario exterior previamente reconocido. El perfil determina la interpretación; una lista o un binario ordinario no se interpreta por apariencia. Una trayectoria hija conserva historia propia pero no necesariamente autoridad independiente.
## 3. API histórica
World.history(rutaFrontera,{from,to}) retorna scope, profile, cut local, rootCut, intervalo [from,to) y registros con position (base cero), rootCut (corte exterior base uno), event y hex exacto. [] consulta raíz. Una ruta no histórica se rechaza, no se devuelve silenciosamente la historia de otro contexto. World.export(scope,end) exporta prefijo exacto (end es cantidad de registros). World.at(corteExterior) reconstruye una instancia histórica independiente por replay. World.read(ruta,{enterFinal:false}) distingue descriptor de trayectoria de geometría interior. La lectura histórica no anexa. El cursor incremental de RC.4 se conserva.
## 4. Reconocimiento conjunto TX
Nuevo tratamiento experimental exterior ["TX",[],[origin,checks,events]]. World.transaction(origin,checks,events). Checks: pares [rutaGlobal,respuestaEsperada] evaluados en un mismo corte previo; ej. [[rutaEstado,["value","solicitada"]]]. Events: tratamientos locales de raíz, incluidas extensiones APPEND y MOUNT; sus sufijos llevan K5B del perfil interior. No se permite TX dentro de TX/hijas ni fabricar MOUNT_LOCAL. Un TX es un solo marco exterior; las extensiones interiores conservan sus propios marcos y corte exterior de procedencia. Se planifica en overlay y se consolida únicamente si todo es admisible. Una falla tardía no consolida las hijas anteriores. La cola serializa el corte por instancia.
El origen es una clave textual estable (hasta 200 unidades JS según perfil). Reenvío idéntico retorna el corte reconocido sin anexar ni repetir efectos. El mismo origen con bytes distintos rechaza. Replay estricto rechaza duplicados físicos de TX y reconstruye recibos. No constituye identidad autenticada de actor. Los tratamientos heredados submit/write sin TX aún permiten operaciones sin reconocimiento de origen; la autoridad comercial debe imponer un contrato de admisión que no deje eludir las condiciones. Las precondiciones ejemplificadas no son una máquina comercial universal, ni garantizan por sí solas pago real, envío o autorización. No hay idempotencia general para APPEND sin TX.
## 5. Casos ejecutados
Venta V1: solicitada, confirmada, pagada, despachada, entregada. Confirmar cambia estado y descuenta dos unidades del stock 10→8 en un solo TX; reenvío exacto conserva 8. Venta V2 permanece solicitada. La entrega tiene estados preparado, despachado, entregado y guía. Un error en stock o hash revierte cambios de venta y entrega. Se consulta un corte donde la venta estaba pagada y la entrega aún no existía. Proyecto P1: colaboradores como tabla; tarea como trayectoria. Dos intenciones con precondición pendiente compiten; solo una se reconoce. Un replay reproduce estado, historial, prefijos y recibos.

## 7. Límites y siguientes garantías
Map y overlay en memoria: no se demuestra durabilidad física, CAS multiinstancia, recuperación tras apagón, autoridad independiente, autenticación, autorización o cooperación C/Q/R. El resultado de TX no se confunde con un protocolo de red. El cuerpo experimental usa JSON y hexadecimal, K5B intacto (1 MiB máximo por cuerpo); no se optimizó representación. History devuelve un rango en memoria, no un stream físico. La garantía de replay y atomicidad lógica es para el escenario y propiedades probadas. Antes de considerar estable: integrar autoridad/contrato obligatorio, persistencia transaccional, recuperación, pruebas de múltiples instancias y réplicas. Mantener el criterio de fenómenos históricos separado de decisiones de optimización.
