01 · Principios preservados

La trayectoria es append-only; un prefijo adquirido y verificado permanece inmutable. La primera aparición constitutiva asigna posición, las siguientes reutilizan. Las tablas, parámetros, entidades, vectores e índices se derivan de la trayectoria mediante el recorrido determinista. Los valores pueden evolucionar; las posiciones históricas no. Las celdas dispersas distinguen ausencia, nulo, cero y false. Q es una proyección de la historia local L, no toda L. R es un vector M3E1; C es la historia canónica reconocida.

Tₙ₊ₘ=Tₙ∥ΔT
Derivar(T∥Δ)=Recorrer(Derivar(T),Δ)
D privado ≠ D canónico ≠ D operativo

PAO conserva bytes sin conocer contratos ni autoridad. K2P, K4B, K5B, T13, T100, T101, T102 y T111 se mantienen. El formato T111 sigue usando identidad nombrada del nodo y posición Q, no índice de N. Véase la documentación 2.0.0 conservada en el paquete como referencias/Qipu-2.0.0-README.html.

02 · N: una trayectoria de localidades

El servidor arranca con N vacío y C con el génesis comercial de la demo. No preconstituye A, B ni C como nodos. Un nombre de localidad estable se reconoce una sola vez; el orden de N determina su índice. Q y R son archivos distintos para cada nombre. N contiene un marco K5B T112 por identidad, no una lista mutable, ni una tabla de estados, ni un registro de sesiones.

N=(j₀,…,jₙ₋₁), sin duplicados
p(j)=posición de primera aparición
Archivos lógicos remotos=2n+2 (N,C y Q/R por localidad)

El archivo authority.lock y las intenciones durables de PAO son mecanismos físicos auxiliares, no nuevas historias. La identidad del nodo es texto ASCII exacto, de 1 a 32 caracteres, con letra inicial, seguido de letras/dígitos/guiones/subrayados; distingue mayúsculas. Se eligió para tener nombres de archivos seguros, no como esquema de autenticación.

03 · Local primero, reconocimiento después

→

→
AutoridadResolver y adquirir C/R.

El selector es ahora un nombre editable; se abre explícitamente la identidad y se descubre el listado de localidades locales desde las claves L de IndexedDB. Abrir crea el espacio L vacío si falta, no constituye la identidad remota. La primera publicación realiza el reconocimiento remoto de forma idempotente. Puede adquirirse C antes de reconocer la localidad. R y Q remotos solo son accesibles después de N. No se pide conexión para constituir localmente. Una recarga completa sin internet sigue fuera de alcance: no hay Service Worker.

El navegador mantiene cada L/C/R como bloque de bytes dentro de IndexedDB. La transacción compare-and-append compara el prefijo esperado y solo lo extiende; si otra pestaña lo modificó, aborta y exige reconstruir antes de reintentar. No se borra el pasado. Los derivados operativos son reconstruibles y no son fuente de verdad.

04 · Contrato de registro y API

T112 es una envoltura K5B con cuerpo UTF-8 JSON {"node":"Bodega"}. Un único escritor lógico (la autoridad) serializa las constituciones. La posición de N no se codifica en el cuerpo: emerge al recorrerlo. Los nombres de archivo se derivan determinísticamente de la identidad; no se persisten URLs arbitrarias.

OperaciónResponsabilidad
POST register?node=jConstituir o reconocer la identidad; devuelve node, index, replayed.
GET nodesListar identidades en orden de N.
GET head/cut/read stream=NLeer y constatar el prefijo de registro de localidades.
POST submitSolo nodo reconocido; posición Q y offset esperados.
GET pending / POST decideRecorrer N, resolver Q por posición de R; C antes de R=1.

La API conserva head, cut y read de Q/R/C y los demás contratos de 2.0.0. Las respuestas M3E1 ocupan un byte. No se reescriben registros previos. El registro N es una autoridad de identidades, no un mecanismo de seguridad: reconocer un nombre no prueba quién lo controla.

05 · Atomicidad lógica del registro

bajo lock de autoridad:
si j ∈ N: verificar existencia de Qⱼ y Rⱼ; devolver posición anterior
si j ∉ N: preparar Qⱼ y Rⱼ vacíos (o reutilizar vacíos)
constituir T112(j) en N mediante PAO
devolver posición de primera aparición

La visibilidad lógica nace exclusivamente del append a N, posterior a preparar ambos archivos. Una caída entre la preparación y N deja archivos vacíos no visibles por API, recuperables con el mismo nombre; no hay estado de alta separado. No se adopta un huérfano no vacío. Si N contiene j y falta Q/R, la operación falla en lugar de recrear una historia potencialmente perdida. El lock serializa concurrencia; PAO conserva su intención durable y garantiza su propio append bajo sus supuestos. No es una transacción física multiarchivo.

La autoridad reconoce solicitudes por Qⱼ[|Rⱼ|]; si aprueba, constituye C con origen y después R=1. Si se interrumpe, el origen recupera R sin duplicar. Si rechaza, R=0 sin efecto en C. El lector canónico valida sintaxis de origen y unicidad; la autoridad comprueba además existencia y contenido de la solicitud contra los Q de N.

06 · Adquirir y constatar

N, Q y C son secuencias de marcos variables; R es un vector fijo de un byte por respuesta. Conservar (posición, offset) para adquirir el sufijo. El lector no vuelve a descargar un prefijo legítimamente adquirido. La demo recalcula hashes de prefijo y conserva bloques completos; no afirma procesamiento O(1) total. El mismo corte canónico y el mismo intérprete determinista implican igualdad de derivados; solicitudes y hechos privados no necesitan coincidir entre localidades.

09 · Alcance

Sin autenticación: solo localhost o entorno aislado. No confundir publicación de código con despliegue de autoridad. La identidad nombrada debe ser única por localidad; repetir el nombre desde otro dispositivo sin autorización no es seguro. Una restauración requiere preservar N, Q/R/C y L/C/R; la pérdida física externa no es recuperable por un nombre. No se ha probado IndexedDB en navegador en este entorno, ni fallos eléctricos reales, ni despliegue remoto. No se realizaron pruebas de millones de registros por decisión de alcance.

Se eligió 2.1.0 como ampliación funcional experimental: cambia inicialización y registro de nodos, conserva CPA y los contratos canónicos, mantiene PAO 1.1 byte a byte. Qipu 2.0.0 permanece intacto como referencia. La coherencia matemática no sustituye pruebas de implementación o garantías del almacenamiento.
