01 · Axiomas constitutivos

Una trayectoria T es una sucesión ordenada de registros completos. Toda extensión preserva exactamente el pasado. La posición de un registro no se negocia ni se anticipa: emerge al constituirlo.

Tₙ₊ₘ = Tₙ ∥ ΔT
∀ i < n : Tₙ₊ₘ[i] = Tₙ[i]
Dₙ₊ₘ = Recorrer(Derivar(Tₙ), ΔT)

Un registro válido puede cambiar un valor derivado, pero no modifica el registro histórico que lo precede. La identidad, la posición, el parámetro y el valor son conceptos distintos. Los índices, tablas, vistas y snapshots son reconstruibles. El lector adquiere un prefijo; nunca necesita tratar el pasado como una base de datos que debe actualizarse fila por fila.

ConstituciónAgregar hechos completos.
AdquisiciónLeer solo lo desconocido.
DerivaciónComputar el significado de los hechos.
ConstataciónComprobar correspondencia y coherencia.

02 · Constitución por primera aparición (CPA)

En 1.0.0 existían contratos explícitos para constituir tablas, vectores y entidades. En 2.0.0 el nuevo contrato de afirmación nombrada T13 no tiene un bit CREATE/UPDATE. Su semántica es la misma si la identidad se conoce o no. Es el recorrido, no la declaración de creación, el que determina la estructura.

Antes · instrucción
CREATE Producto
CREATE Nombre
CREATE SKU-A
SET (0,0,0, Camisa)
La generación de instrucciones dependía de saber qué faltaba.
Ahora · afirmación
(Producto, SKU-A, Nombre, texto, Camisa)
Un único hecho nombrado. No contiene posiciones anticipadas ni órdenes CREATE.

Para cada espacio de identidades S — tipos, parámetros de un tipo o identidades de un tipo — sea U(S,T) la secuencia de sus primeras apariciones constitutivas en el orden de recorrido. Se descartan repeticiones para construir esa secuencia, no se descartan los registros históricos que las contienen.

resolver(S, x):
si x ∈ U(S,T): posición ya derivada
si x ∉ U(S,T): posición = |U(S,T)|; extender U
pₛ(x) = rango de la primera aparición de x dentro de S

Si dos identidades aparecen en el mismo registro compuesto, se usa el orden inequívoco del contrato y del lote. Los tres espacios son independientes; no existe una posición global de parámetro ni de entidad. La identidad se compara exactamente por su texto UTF-8 válido; no se normaliza mayúsculas, espacios o Unicode de manera implícita. El laboratorio restringe nombres a 1–200 bytes y rechaza BOM inicial en afirmaciones; K2P preserva BOM como carácter general.

La comprobación de existencia no desaparece de la matemática. Desaparece como instrucción o fase independiente de registro. La consulta del índice es una operación interna de derivación. La autoridad sigue verificando coherencia, compatibilidad de tipo, límites y reglas de negocio. Para afirmaciones compatibles emite el mismo T13, sin fabricar CREATE según el estado anterior.

Una mención referencial no constituye. Una venta con SKU inexistente falla en vez de crear un producto accidentalmente. La autoridad puede reconocer una afirmación repetida sin cambiar ningún valor; sigue constituyendo un acontecimiento canónico con origen, necesario para constatar su reconocimiento.

Para una venta el contrato T7 conserva referencias posicionales: tabla, vector de stock, líneas de (entidad, cantidad, precio). Los nombres se resuelven en la autoridad; el lector ya no repite esa resolución. No se convierte una referencia numérica inexistente en declaración.

04 · Cómo emergen tablas, parámetros y entidades

El génesis contiene tres afirmaciones de datos para SKU-A: Nombre=Camisa, Precio=35000, Stock=20. No existe una tabla preconstituida en el código. El génesis es un lote inicial de datos de la demo, no una regla universal del mecanismo.

iIdentidadV0 NombreV1 PrecioV2 StockV3 Color
0SKU-ACamisa3500020∅
1SKU-B∅∅∅Azul

V[t,v][i] es una celda dispersa. Agregar una entidad no exige recorrer los vectores; agregar un vector no exige recorrer las entidades. ∅ significa que no existe el valor; no equivale a null ni a cero ni a false. T9 establece null explícito y T10 retira un valor (no elimina la identidad), salvo en stock, que exige naturales. Los nombres se indexan con mapas reconstruibles por espacio; PHP usa claves prefijadas para evitar coerción de claves numéricas. Los índices se generan al recorrer y no son fuente de verdad.

La búsqueda de identidad tiene costo esperado O(1) respecto al número de identidades con índices hash y nombre de longitud acotada; se añade el costo de procesar sus bytes. El modelo actual clona estados y mantiene historia en memoria para validar; no confundir esa propiedad local con el costo total de una petición.

05 · Localidad: primero constituir, luego publicar

Lⱼ contiene toda la actividad registrada de un nodo: notas, hechos estrictamente locales y solicitudes. Qⱼᴸ es la subsecuencia de registros T101 de Lⱼ. Un hecho T102 puede constituir exactamente las mismas estructuras CPA, pero en un espacio privado derivado de L, no en C. No toda acción local es una solicitud.

L[0]Nota T100
L[1] → Q[0]Solicitud T101
L[2]Hecho privado T102
L[3] → Q[1]Solicitud T101
Qⱼᴸ = Proyectar_T101(Lⱼ)
Qⱼ remoto ≼ Qⱼᴸ
posición Q ≠ posición L (en general)

IndexedDB conserva separadamente L, Cⱼ y Rⱼ para cada nodo A/B. Se valida un registro antes de anexarlo, se compara el prefijo esperado dentro de una transacción y se confirma antes de intentar publicar por red. La publicación copia los marcos T101 originales, no los vuelve a crear. Si falla, el mismo Q se completa después por posición y offset. No hay cola independiente.

Los derivados estrictamente locales se muestran por separado. Los efectos compartidos provisionales se calculan sobre el prefijo canónico conocido. El acto local no confiere autoridad de constitución canónica. Las posiciones provisionales pueden diferir de las canónicas; se resuelven nombres nuevamente al reconocer. El código local no sobrescribe su historia al incorporar C.

06 · La autoridad reconoce; PAO persiste

Los cinco archivos lógicos remotos son Q/R por nodo más C compartida. La autoridad se emula con una página y una API PHP, sin autenticación, únicamente en entorno aislado. Su regla de orden es la siguiente solicitud Qⱼ[|Rⱼ|]. Las respuestas se constituyen en orden; las constituciones canónicas se serializan con un lock de autoridad. No existen callbacks ni mensajería entre nodos.

AceptarConstruir hechos nombrados o referenciales, validar lote completo, anexar C con procedencia (nodo, posición Q), después escribir R=1.
RechazarEscribir R=0. C no contiene el efecto solicitado.
InterrupciónSi C ya contiene el origen y falta R, recuperar R=1 sin duplicar el hecho.

La aceptación de una afirmación sin cambio de estado aún produce un registro canónico con origen. No hay log separado de decisiones. La procedencia es evidencia de reconocimiento, no un atributo que el usuario deba asignar a cada celda. En esta configuración, la canónica se constituye en el servidor PHP: el nodo necesita red para solicitar/reconocer. Una autoridad offline es otro despliegue posible, no implementado aquí.

07 · PAO: persistencia opaca y posiciones físicas

PAO no interpreta tipos, productos, solicitudes, ni CPA. Su objeto es una cadena de bytes confirmados. El mecanismo original de PAO 1.1.0 se usa byte por byte sin modificaciones, mediante la clase Storage y no mediante su endpoint HTTP original.

CREATE(id) → archivo vacío
HEAD(id) → frontera confirmada C
READ(id, offset, length) → bytes de un corte confirmado
APPEND(id, offset, bytes) → nuevo bloque o replay idempotente

El offset es en bytes, no índice de registro. La frontera confirmada puede diferir del EOF físico durante la recuperación. PAO usa flock, una intención durable PAO1, fsync, publicación por rename y recuperación por sufijo. No acepta huecos ni sobrescritura; un rango ya confirmado con exactamente los mismos bytes es un reintento. El lock de autoridad coordina además el protocolo multiarchivo; PAO solo coordina un archivo.

Modelo de durabilidad: PHP 8.1+ de 64 bits, filesystem POSIX local que respete flock y fsync, inode estable, directorio privado, escritores cooperativos y sin modificaciones externas. No certifica NFS, fallos eléctricos reales, corrupción arbitraria ni hosting compartido. El archivo de intención temporal no es otra trayectoria. Consulte referencias/PAO-1.1.0.md dentro del ZIP para su contrato íntegro.

08 · Adquisición incremental, no sincronización de copias

Prefijo conocido0123
+
Extensión adquirida45
→
Nuevo conocimiento0…5; pasado intacto

El lector conserva identidad de trayectoria y frontera de bytes. Para ancho fijo b, offset(i)=b·i. En registros variables, el límite emerge del recorrido anterior. La API de lectura acepta offset y longitud y devuelve X-Confirmed-End. Se verifica el corte y se procesa el sufijo, no se vuelve a descargar el prefijo. Si no hay bytes nuevos, solo se conoce que no había extensión en el corte observado; error de red no es ausencia.

Cⱼ ⪯ C
Derivar(Cⱼ ∥ ΔC) = Recorrer(Derivar(Cⱼ), ΔC)

La constatación de esta demo compara SHA-256 de los bytes del prefijo local con SHA-256 del mismo prefijo remoto. No transfiere el pasado, pero PHP y el lector vuelven a calcular el hash del prefijo. Un futuro mecanismo de compromiso incremental autenticado puede reducir ese costo. Las marcas M-E detectan ciertas alteraciones posicionales, no todos los errores ni autenticidad.

El mecanismo general de topología lógica mediante nombres (FOLLOW al último slot, SPAN a todos, EMIT adquisición y verificación, TRAYECTORIA interpretación) sigue siendo la arquitectura de referencia; esta demo usa URLs directas a la API y no implementa ese recorrido topológico completo.

La consistencia offline es relativa al conocimiento local y no garantiza el inventario global actual. La autoridad puede denegar una solicitud incompatible. Los efectos provisionales pueden volverse incompatibles con C reciente; se muestran como conflicto, sin eliminar la historia.

11 · Instalación, uso y API de prueba

Descomprimir el ZIP. Desde qipu_2.0.0, ejecutar en terminal (servidor de desarrollo PHP):

mkdir -m 700 data-v2
php -S 127.0.0.1:8080 -t public

Abrir http://127.0.0.1:8080/. Se necesita PHP 8.1+ de 64 bits y navegador moderno con IndexedDB/Web Crypto. Node.js solo se necesita para las pruebas. La aplicación no requiere CDN, dependencias npm ni Service Worker. La página abierta permite operar offline; no garantiza una primera carga sin conexión.

Laboratorio no autenticado. No exponer en internet ni usar con mercancía o datos reales. Los controles de la interfaz no son autorización. Conservar los datos fuera del document root. Se usa data-v2 y la base IndexedDB qipu-pao-v2 para no reinterpretar el historial anterior. No apuntar QIPU_ROOT a un directorio antiguo. No hay migración automática.

Ejemplo de afirmación de producto: el botón producto envía nombre, precio y stock absoluto en un lote de tres T13. Una repetición compatible reutiliza identidad y actualiza valores, incluida la asignación absoluta de stock. No confundir con incremento de stock o reintento: un nuevo acto idéntico en otra posición de Q es un nuevo acontecimiento. El mismo acto en la misma posición se reintenta sin duplicar.

Secuencia manual sugerida

Adquirir C en A y B; desmarcar red en A; constituir una nota y una afirmación privada, luego solicitar una venta. Volver a marcar red y publicar Q. Consultar pendientes en autoridad, aceptar. Adquirir primero R en A y observar el estado provisional; adquirir C y verificar que el descuento no se duplica. En B adquirir C antes de R. Probar nuevo parámetro Color, repetir la misma afirmación y luego enviar una incompatible con otro tipo. Constatar prefijos y reconstruir desde registros.

13 · Alcance, decisiones y evolución

Se eligió 2.0.0 por el cambio incompatible de la envoltura canónica T110→T111, la semántica constitutiva T13 y el nuevo formato de derivados. Es una versión experimental del prototipo integrado, no una publicación de producción. El paquete anterior se conserva; PAO no se modifica.

El compilador de afirmaciones produce el mismo contrato sin preguntar si se trata de alta o actualización. La validación previa de la autoridad y el recorrido todavía deben consultar índices para constatar coherencia. El cliente conserva blobs completos en IndexedDB con compare-and-append transaccional, no un store por registro. El replay canónico de PHP aún recorre la historia y la recuperación usa estados anteriores para cotejar efectos; la demo limita cada flujo a 4 MiB, no mide rendimiento de producción. El navegador recalcula derivados provisionales sobre el corte conocido y clona estados candidatos. La adquisición HTTP es incremental; el procesamiento y la persistencia local tienen optimizaciones pendientes.

Quedan fuera de esta versión: autenticación, roles, permisos de autoridad, IDs de trayectoria autenticados, compromisos de prefijo eficientes, topología FOLLOW/SPAN/EMIT completa, migración, paginación de grandes flujos, importadores reales, garantías de mercancía offline y alta disponibilidad. Un nuevo registro puede incorporar referencias nombradas o posicionales según contrato; compactar afirmaciones repetidas en nuevas representaciones requeriría otra versión. No se confunde esta propuesta con un formato ya probado en producción.

Regla de evolución: claridad conceptual → contrato determinista → prototipo → pruebas reproducibles → README HTML autónomo → ZIP versionado → índice documental. Preservar el pasado también en el desarrollo.
